# hanweb_catholic

**광고·유료 등급·회원가입 없이 누구나 쓰는 무료 문서 편집기입니다.** 본당과 모임의 문서 작업을 포함해 누구나 사용할 수 있습니다. React 19와 TipTap 3/ProseMirror를 기반으로, 원본 HanWeb의 문서 편집·복구·파일 변환 기능을 유지합니다.

별도 API 키나 유료 변환 서버가 필요하지 않습니다. 앱을 열면 바로 입력하거나 파일을 불러올 수 있습니다. 문서 편집과 파일 변환은 기기 안에서 수행하며 문서를 운영 서버로 자동 업로드하지 않습니다. 브라우저의 자동 저장본은 다른 기기와 동기화되지 않습니다.

기준 소스는 [yeuxpurs/hanweb23의 codex/hanweb-reliability-20261005 브랜치](https://github.com/yeuxpurs/hanweb23/tree/codex/hanweb-reliability-20261005), 커밋 [`a25fad6623880ab96d4aa7d9bbf8cc676c9a7241`](https://github.com/yeuxpurs/hanweb23/commit/a25fad6623880ab96d4aa7d9bbf8cc676c9a7241)입니다.

## 바로 사용하기

**[hanweb_catholic 바로 사용하기](https://yeuxpurs.github.io/hanweb_catholic/)** — 설치나 회원가입 없이 접속할 수 있습니다.

1. 브라우저에서 앱을 열고 새 문서를 작성하거나 파일을 엽니다. **서식으로 시작하기**에서 준비된 양식을 고를 수도 있습니다.
2. 글자·문단·표·그림을 편집하고, 필요한 경우 용지·머리말·꼬리말을 설정합니다.
3. HWPX·DOCX·TXT·HTML 또는 `.hanweb` 백업으로 저장합니다. PDF는 인쇄 미리보기에서 브라우저의 **PDF로 저장**을 선택합니다.
4. 자동 저장과 별도로 중요한 문서는 파일 백업을 내려받아 보관합니다.

주요 단축키는 `Ctrl+O` 열기, `Ctrl+S` 저장, `Ctrl+F` 찾기, `Ctrl+H` 바꾸기, `Ctrl+P` 인쇄, `Ctrl+Z` 실행 취소, `Ctrl+Y` 다시 실행, `Ctrl+Enter` 쪽 나누기입니다. 전체 메뉴와 단축키 안내는 앱에서 확인할 수 있습니다.

## 무료로 제공하는 기능

- **문서 편집:** 글꼴·크기·색·강조·위/아래 첨자, 문단 정렬·간격·들여쓰기, 제목과 목록, 찾기·바꾸기, 실행 취소·다시 실행.
- **표와 그림:** 행·열 추가/삭제, 셀 병합/분할과 속성, 그림 넣기·붙여넣기·드롭, 비율 유지 크기 조절, 대체 텍스트와 캡션.
- **6가지 시작 서식:** 빈 문서, 회의록, 본당 주보, 행사 안내문, 전례·프로그램 준비표, 공문·협조 요청. 입력란을 직접 채우는 편집 가능한 양식입니다.
- **작성 보조:** 링크 삽입·수정·해제, 특수문자, 서울 시간 기준 오늘 날짜 삽입, 제목 탐색, 도구를 접는 집중 모드.
- **문서 통계:** 공백 포함/제외 글자 수, 띄어쓰기 기준 단어 수, 선택한 글자 수, 문단·표·그림 수.
- **파일과 인쇄:** HWPX·DOCX·TXT·HTML 가져오기/내보내기, HWP 가져오기 시도, PDF 보기, 인쇄/PDF 출력, 전체 문서 백업.
- **저장과 복구:** 브라우저 자동 저장, 복구본 선택, 문서 전환 전 저장, 다중 탭 충돌 감지와 파일 백업.

이 기능들에 유료 잠금이나 광고 시청 조건은 없습니다. 형식별 지원 범위는 아래 표를 확인하세요.

## 설치와 오프라인 사용

최초 접속은 인터넷이 필요합니다. HTTPS 또는 localhost에서 앱의 오프라인 준비가 완료되면 같은 브라우저에서 연결이 끊겨도 다시 열어 편집할 수 있습니다. 브라우저가 제공하는 **앱 설치 / 홈 화면에 추가** 메뉴로 별도 창에서 사용할 수도 있습니다. 설치 메뉴와 저장 공간 보존 정책은 브라우저마다 다릅니다.

서비스 워커는 앱의 HTML·JavaScript·CSS·아이콘만 캐시합니다. 문서 파일은 이 캐시에 넣지 않습니다. 업데이트는 이전 앱의 탭을 모두 닫은 뒤 다음 실행에 적용되므로 편집 도중 강제로 새로고침하지 않습니다. 웹사이트 데이터 삭제, 비공개 모드, 브라우저의 저장 공간 정리 후에는 오프라인 캐시와 자동 저장본이 사라질 수 있습니다. 외부 웹 링크 등 인터넷 자원은 오프라인에서 사용할 수 없습니다.

## 실행과 검증

Node.js 22와 pnpm 10.4.1을 사용합니다. pnpm-lock.yaml을 유지하세요.

```sh
corepack enable
corepack prepare pnpm@10.4.1 --activate
pnpm install --frozen-lockfile
pnpm dev
pnpm check
pnpm test
pnpm build
pnpm preview
```

`pnpm build`는 정적 파일과 버전별 오프라인 서비스 워커를 `dist/public`에 생성합니다. 서버 실행이나 환경 변수 없이 빌드할 수 있으며 기본 경로는 상대 경로 `./`입니다. 결과 폴더를 HTTPS 정적 호스팅에 올리면 됩니다. HTML 파일을 `file://`로 직접 더블 클릭하는 방식은 지원하지 않습니다.

`VITE_BASE_PATH`를 지정하면 고정 하위 경로로 빌드합니다. PowerShell 예시:

```powershell
$env:VITE_BASE_PATH = '/hanweb_catholic/'
pnpm build
pnpm preview
```

브라우저에서는 미리보기 주소의 `/hanweb_catholic/` 경로를 엽니다. 기본 상대 경로로 돌아가려면 해당 환경 변수를 해제하고 다시 빌드합니다.

## 무료 정적 배포

1. GitHub에 `hanweb_catholic` 저장소를 만들고 이 소스를 `main`에 올립니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. **Actions → Deploy hanweb_catholic → Run workflow**를 실행하거나 `main`에 새 커밋을 올립니다.
4. 배포 작업이 성공한 후 **Settings → Pages**의 실제 게시 주소를 확인합니다.

워크플로는 저장소 이름으로 경로를 자동 설정하고 타입 검사·단위 테스트·빌드를 통과한 파일만 게시합니다. 공개 사이트 접속자는 GitHub 계정이 필요 없습니다. GitHub Pages의 사용 가능 여부와 무료 제공 범위는 저장소 공개 설정과 계정 정책에 따라 달라집니다. 유료 서비스 가입이나 결제 정보는 이 앱의 필수 조건이 아닙니다. `dist/public`은 다른 정적 호스팅에도 배포할 수 있습니다.

배포물에는 광고 설정·광고 이미지·Manus 진단 스크립트·외부 Google Fonts 요청이 들어가지 않습니다. 기기에 설치된 한글 글꼴을 사용하므로 환경에 따라 글꼴과 줄바꿈이 달라질 수 있습니다.

## 실제 파일 지원

| 형식 | 불러오기·편집 | 같은 형식 저장 | 다른 형식 출력 |
|---|---|---|---|
| HWPX | 본문·주요 서식·표·그림·단일 용지 설정 | 실제 HWPX ZIP/XML 생성 | DOCX, 인쇄/PDF, HanWeb 백업 |
| HWP | 상세 HWPX 변환 시도 또는 명시적 텍스트 추출 후 편집 | 미지원 | HWPX, DOCX, 인쇄/PDF |
| DOCX | 주요 OOXML 서식·목록·병합 표·그림·단일 용지 설정 | 실제 OOXML ZIP 생성 | HWPX, 인쇄/PDF, HanWeb 백업 |
| DOC | 미지원 | 미지원 | 미지원 |
| PDF | Chrome/Edge 기본 PDF 뷰어. 원문 편집·주석·OCR 미지원 | 현재 편집 문서를 브라우저 인쇄의 PDF 저장으로 출력 | PDF를 편집 문서로 변환하는 기능 미지원 |
| TXT | UTF-8 텍스트, 줄바꿈·빈 줄을 불러오기 | UTF-8 텍스트 다운로드. 서식·그림·표 구조는 제외 | HWPX, DOCX, HTML, 인쇄/PDF |
| HTML | 본문·주요 인라인 서식·표·내장 그림. 스크립트와 외부 자원 제외 | 독립 HTML 다운로드. 복잡한 웹 기능·정확한 쪽 배치는 보존하지 않음 | HWPX, DOCX, TXT, 인쇄/PDF |
| .hanweb | 전체 편집 JSON/HTML·용지 설정 | JSON 백업 다운로드 | HWPX, DOCX, 인쇄/PDF |

확장자만 바꾸지 않습니다. 필수 패키지/XML/HWP 서명을 검사하고 가져오기가 실패하면 현재 문서를 유지합니다. 형식별 제한을 안내합니다.

TXT는 UTF-8 기준이며 다른 문자 인코딩의 파일은 UTF-8로 변환한 뒤 불러오는 것이 좋습니다. HTML은 문서 편집에 필요한 요소와 속성만 허용합니다. 실행 코드·폼·프레임·외부 스타일·원격 그림 등은 제외하므로 웹페이지 전체를 그대로 복제하는 기능은 아닙니다. HTML의 내장 그림은 지원하는 래스터 이미지의 data URL만 보존합니다.

HWPX/DOCX에는 HanWeb 재열기용 HanWeb/document.json을 추가합니다. 본문 XML·그림의 SHA-256이 일치할 때만 사용하며 외부 프로그램에서 수정된 패키지는 표준 문서 부분을 다시 해석합니다. 높은 HanWeb 재열기 보존율이 한컴이나 Word의 동일한 표시 결과를 뜻하지 않습니다. HWPX 외부 머리말·꼬리말·쪽 번호·명시적 나누기 등은 제한됩니다. DOCX는 단일 구역, 텍스트 머리말/꼬리말, PAGE 필드, 그림의 텍스트 캡션을 지원합니다. 각주·변경 추적·복잡한 도형·다중 구역은 지원하지 않습니다.

## 편집과 페이지

글자/문단 서식, 제목 스타일, 다단계 목록, 실제 찾기·바꾸기, 표 행/열·셀 병합/분할·속성, 그림 파일/붙여넣기/드롭·비율 유지 크기 조절·대체 텍스트·캡션, 제목 탐색을 제공합니다. 주요 도구는 선택 영역의 혼합 서식을 표시합니다. 문서마다 실행 취소 기록을 분리하고 찾기 전체 바꾸기는 한 번에 취소합니다.

편집 화면은 연속 본문입니다. A4/A3, 방향, mm 여백, 머리말/꼬리말/쪽 번호를 문서 상태로 관리합니다. 실제 페이지 수와 분할은 읽기 전용 인쇄 미리보기에서 측정합니다. 편집기 높이로 가상의 쪽 경계를 표시하지 않습니다. 미리보기와 인쇄/PDF는 같은 고정 치수·페이지 배치 결과를 사용합니다. 화면 배율은 출력 치수를 변경하지 않습니다.

긴 문단을 글자 경계에서 나누고 제목과 다음 문단·외톨이 줄을 완화하며 표 제목 행을 반복합니다. 병합 행 그룹을 쪼개지 않습니다. 한 페이지보다 큰 그룹이나 개체는 경고와 함께 축소될 수 있습니다. 편집 화면에서 직접 실제 페이지를 동시에 편집하는 기능은 후속 작업입니다.

PDF 저장 시 인쇄 창에서 문서 용지 크기, 배율 100%, 여백 없음, 브라우저 머리글/바닥글 끄기를 확인하세요. 글꼴과 외부 프로그램의 배치 엔진에 따라 줄바꿈과 페이지 수가 달라집니다.

## 자동 저장과 복구

HanDocument v2는 문서 ID·revision·TipTap JSON·HTML·파일명·용지/머리말/꼬리말을 포함합니다. IndexedDB의 문서별 레코드와 전환 전 스냅샷을 사용합니다. 원본 HanWeb의 문서는 `.hanweb` 백업 파일로 옮길 수 있습니다.

평상시 지연 저장·주기 저장·가시성 변경 저장을 수행하며 IME 조합 중에는 저장을 미룹니다. 문서 전환은 이전 문서와 새 후보를 저장한 뒤 본문을 교체합니다. 실패를 표시하고 재시도·복사본·백업 다운로드를 제공합니다. 다른 탭의 revision이 앞서 있으면 덮어쓰기를 차단합니다. 실패/종료 시 localStorage 긴급 복구는 최선의 추가 수단이며 저장 완료로 간주하지 않습니다. 저장소 삭제·용량 부족에 대비해 파일 백업도 보관하세요.

복구 창을 닫아도 기록을 삭제하지 않습니다. 삭제는 별도의 명시적 동작입니다. 시작 시 비동기 복구가 끝날 때까지 본문을 보호하고 새 문서·가져오기·복구의 실행 취소 기록을 초기화합니다.

## 구조

- client/src/editor/document.ts: 문서 모델과 용지 설정.
- editor/useDocumentSession.ts, utils/autosave.ts: 저장·전환·복구·충돌.
- editor/DocumentExtensions.ts, useHanwebEditor.ts: 문서 속성과 편집 엔진.
- editor/FindReplace.tsx, search.ts, EditingTools.tsx, DocumentOutline.tsx: 편집 도구.
- editor/templates.ts: 여섯 가지 시작 서식.
- editor/portableFormats.ts, editingHelpers.ts: TXT/HTML 변환, HTML 정리, 링크·날짜·특수문자 보조.
- editor/pagination.ts, components/PrintPreview.tsx: 측정 기반 인쇄 배치.
- components/PdfViewer.tsx: 브라우저 기본 PDF 보기.
- docx/, hwpx/, hwp/: 형식별 변환과 검증.
- pages/HanWebEditor.tsx: 메뉴/리본과 사용자 흐름.

기존 JSZip, hwp-convert, CFB/pako를 사용합니다. `scripts/build-offline.mjs`는 빌드 파일 목록과 내용 해시로 오프라인 캐시를 만듭니다. `server/`는 원본의 정적 파일 실행 보조이며 기본 빌드에는 포함되지 않습니다. HWP 저장·OCR·상용 문서 변환 서버가 아닙니다.

## 호환성 범위와 남은 조건

2026년 10월 27일 작업에서 타입 검사, 단위 테스트 18개, 프로덕션 빌드를 통과했습니다. 브라우저에서는 HTML 정리 관련 DOM 사례 7개, DOCX/HWPX 다운로드와 재가져오기, 주보 서식과 인쇄 미리보기를 확인했습니다. 프로덕션 앱의 오프라인 준비 후 로컬 서버를 중단하고 새로고침해 앱 실행·문서 복구·HWPX 저장도 확인했습니다. 생성된 서비스 워커는 Node VM 환경에서 요청 시나리오 19개를 통과했습니다. 문서 요청 제외와 경로별 캐시 격리도 검증했습니다. 장기 저장 및 모든 모바일 브라우저의 동작을 보장하는 시험은 아닙니다.

단위 테스트는 검색·문서 속성·표 구조 등을 검증합니다. 개발 전용 `docx/validation.ts`의 종합 문서는 다국어·기호·중첩 목록·병합/긴 표·그림·머리말/꼬리말·A3·나누기를 포함합니다. 실제 Windows 한국어 IME, 인쇄 장치, 외부 편집기와의 호환성은 별도 실사용 확인이 필요합니다.

원본 브랜치의 검증 기록에서는 동일한 A3 DOCX 예제가 HanWeb에서 4쪽, LibreOffice 24.2.5.2에서 3쪽으로 달랐습니다. 한컴과 Microsoft Word에서 모든 파일이 같은 모습으로 표시된다는 보장은 없습니다. 자동 이벤트는 실제 IME 시험을 대체하지 않습니다.

HWP 원본 저장, PDF 원문 편집·OCR, 변경 추적, 각주, 복잡한 도형, 다중 구역과 완전한 페이지 단위 편집은 지원하지 않습니다. Word와 동등한 완성도나 모든 형식의 무손실 변환을 약속하지 않습니다. 지원하는 기능은 모두 무료이며, 이런 기능 제한을 풀기 위한 유료 업그레이드 메뉴는 없습니다.
